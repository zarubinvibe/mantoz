# Конечная цель владельца
Ключевые слова ОБЯЗАН, ЗАПРЕЩЕНО, СЛЕДУЕТ, МОЖЕТ трактуются по RFC 2119 и только в верхнем регистре.

## Что станет истинным
Mantoz закрывает функциональный разрыв с github.com/MatrAIx-ai/MatrAIx-Persona-8B по объективному чек-листу, а не "по духу", и добавляет минимум одно улучшение сверху (Harbor-зависимость вместо вендоринга, pluggable sandbox, тонкий вьювер). Граунд персон в продакшне держится целиком на бесплатных и коммерчески разрешённых данных — платного источника нет ни одного. Планирование живёт в EARS + `docs/DECISIONS.md`, второго источника правды по методологии нет.

## Требования
- REQ-01 [parity.check] Чек-лист паритета, построенный построчно из 7-подсистемного аудита MatrAIx (persona/task-contract/harbor/playground/packages/deployment/testing), ОБЯЗАН на приёмке MVP показывать 0 строк "отсутствует без обоснования".
- REQ-02 [deps.harbor] Исполнение агентов ОБЯЗАНО идти через Harbor (github.com/harbor-framework/harbor) как pip/git-зависимость с LICENSE/NOTICE-атрибуцией, не форком.
- REQ-03 [sandbox.pluggable] В конфиге ОБЯЗАНЫ существовать минимум 2 одновременно доступные реализации `BaseEnvironment`: self-hosted Docker Swarm/k3s (бесплатный дефолт) и Modal (платный opt-in).
- REQ-04 [agents.registry] Реестр агентов ОБЯЗАН содержать не менее 10 CLI/провайдеров, вызываемых через multi-provider клиент (litellm или эквивалент).
- REQ-05 [verify.population] Верификация ОБЯЗАНА быть task-owned (свой верификатор на тип задачи) и запускаться с настраиваемым `n_runs` > 1 на персону, агрегируя результат до отчёта с полями `aggregation_method` и `subgroup_breakdown` — не хардкодом в 1 прогон.
- REQ-06 [ui.thin] UI ОБЯЗАН быть 1 тонким вьювером результатов без сборки второго React-мажора рядом с ним.
- REQ-07 [product.universal] Ядро ОБЯЗАНО работать без хардкода продуктов владельца (TODOCUPS/юрпрактика) — их подключение только через конфиг персон, как любой домен.
- REQ-08 [product.environments] MVP ОБЯЗАН поддерживать все 4 среды теста персоны (survey/chat/web/app) одновременно на дату приёмки, не поэтапно.
- REQ-09 [locale.agnostic] Конфигурация популяции ОБЯЗАНА задавать RU тем же механизмом, что любую другую локаль, без RU-only веток кода.
- REQ-10 [data.ground] Продакшн-граунд персон ОБЯЗАН опираться на источники с явным разрешением коммерческого использования; на 06.09.2026 таким подтверждён Росстат/ЦБ через tochno.st (CC BY 4.0). Новый источник добавляется только после проверки его условий НА СТРАНИЦЕ ВЫДАЧИ ФАЙЛА, а не по описанию проекта.
- REQ-11 [data.bootstrap] Persona1M (Hugging Face, лицензия matraix-research-only) МОЖЕТ использоваться только в dev/test-пайплайне генерации персон.
- REQ-12 [attribution.cite] Документация ОБЯЗАНА цитировать методологию MatrAIx (arXiv:2608.04205 + ссылка на репозиторий) там, где схема/DAG-подход персон заимствован по духу.
- REQ-13 [plan.method] Планирование ОБЯЗАНО идти по схеме Helioz: EARS-требования этого файла + 1 `docs/DECISIONS.md` + словарь терминов, без параллельного дерева GSD.

## Нельзя
- LIM-01 [limits.license] Использовать WVS как источник граунда для коммерческого продукта без отдельной письменной лицензии WVSA ЗАПРЕЩЕНО.
- LIM-02 [limits.license] Использовать сырые данные GSS как граунд без письменного разрешения NORC ЗАПРЕЩЕНО; референс схемы вопросов без сырья не запрещён.
- LIM-03 [limits.license] Использовать данные Левада-центра ЗАПРЕЩЕНО (статус иноагента РФ).
- LIM-04 [limits.paid] Платить за источник данных персон ЗАПРЕЩЕНО, пока не найдена бесплатная замена или владелец лично не согласовал платную лицензию.
- LIM-05 [limits.vendor] Форкать или переименовывать код Harbor вместо атрибутированной зависимости ЗАПРЕЩЕНО.
- LIM-06 [limits.forced-choice] Жёстко фиксировать единственный sandbox-бэкенд в коде ЗАПРЕЩЕНО — новые бэкенды подключаются как pluggable-реализации, не заменой варианта.
- LIM-07 [limits.verify-cut] Сводить верификацию к 1-2 агентам-ревьюерам вместо task-owned population-scale верификатора ЗАПРЕЩЕНО.
- LIM-08 [limits.data-prod] Использовать Persona1M MatrAIx где-либо в продакшн-пути генерации персон ЗАПРЕЩЕНО.
- LIM-09 [limits.planning] Заводить второй источник правды по планированию (GSD `.planning/`, PRD/ROADMAP параллельно EARS+DECISIONS.md) ЗАПРЕЩЕНО.
- LIM-11 [limits.license] Использовать РМЭЗ-ВШЭ (RLMS-HSE) как источник продакшн-граунда ЗАПРЕЩЕНО: условия доступа на странице выдачи файла разрешают только некоммерческое использование и прямо запрещают передачу данных другим пользователям «ни в виде файлов данных, ни в виде вторичной информации» - то есть и производные маргиналы отдавать нельзя. Проверено вживую 06.09.2026.
- LIM-10 [limits.untouchable] Тихо занижать критерий приёмки со "100% функционал либо лучше по чек-листу" до "по духу"/"на глаз" ЗАПРЕЩЕНО.

## Принято по умолчанию
Отдельный проект семьи Olympuz (не модуль Helioz), может дёргать Helioz как библиотеку. Repo приватный до рабочего MVP (не переспрошено явно, стоит подтвердить на первом коммите). Бюджет времени без жёсткого дедлайна, гейт-бюджеты по задачам, не по проекту целиком. Multi-provider доступ к LLM держим с первого дня; ручной rpm/tpm-прокси под throughput чиним по факту упора в лимит, не заранее. Атрибуция двух родов: Harbor — код-зависимость (LICENSE/NOTICE), методология MatrAIx — только цитата в доках, код не берём.

## Вне цели
Каждый пункт несёт ID и заявленную область действия `[покрывает: …]` — список подсистем чек-листа паритета, которые он вправе освобождать. Строка чек-листа со статусом «отсутствует обоснованно» ОБЯЗАНА ссылаться на ID отсюда дословно (`OUT-NN`, ровно две цифры) И принадлежать подсистеме из области действия этого ID. Ссылка прозой, на REQ или на LIM обоснованием не является; нечёткое сопоставление текста ЗАПРЕЩЕНО; настоящий ID, приклеенный к строке вне его области действия, обоснованием НЕ является.

- OUT-01 Международный human-grounding (US-эквивалент через GSS/WVS) на платной основе — ждём бесплатный источник либо отдельное решение владельца платить. [покрывает: persona]
- OUT-02 15 sandbox-бэкендов MatrAIx (E2B/Runloop/Daytona/GKE/Singularity...) сверх Docker+Modal — добавляются pluggable по факту нужды. [покрывает: harbor, deployment]
- OUT-03 Persona 1M (Hugging Face, лицензия matraix-research-only) как продакшн-граунд персон — используется только в dev/test bootstrap (LIM-08), продакшн-граунд строится на бесплатных источниках (REQ-10). [покрывает: persona]
- OUT-04 apps/viewer — второй SPA на другой мажорной версии React — заменён одним тонким вьювером результатов (REQ-06). [покрывает: playground]
- OUT-05 Конкретный список 10+ агентов реестра, схема данных персоны, детали testing/packages/deployment-подсистем аудита. [покрывает: packages, testing, deployment]
- OUT-06 Кластерный прогон масштаба статьи MatrAIx (SLURM, 10 млрд строк, корпус на 8,3 млрд персон) - это объём предвычисленного корпуса, а не возможность: генератор Mantoz выдаёт выборку любого размера по требованию, и гейты качества валидируются на тысячах строк так же, как на миллиардах. Масштабировать после зелёных гейтов, не до. [покрывает: persona, deployment]
- OUT-07 Референс-эвалы масштаба статьи (18 189 прогонов на 8 задачах, 1010 задач в 25 доменах) - исследовательский артефакт публикации MatrAIx, а не функция продукта. Механика прогона и агрегации закрыта REQ-05 и REQ-08. [покрывает: testing, task-contract]
