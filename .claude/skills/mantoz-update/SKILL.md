# Обновление Mantoz

Этот навык обновляет уже поставленную копию. Первая установка идет через `/mantoz-setup`, это другой разговор.

Он работает там, где есть исходники: клон репозитория или распакованный ZIP. Ставили из архива, тогда
обновление выглядит иначе, об этом внизу отдельно.

## Правила

**1. Сначала показать, потом делать.** Сказать, какая версия стоит сейчас и какая опубликована, и
показать список изменений. Решает человек.

**2. Грязное дерево значит стоп.** Есть незакоммиченные правки, назвать эти файлы поименно и
остановиться. Чужую работу не затираем.

**3. Только вперед.** Тянуть `--ff-only`. Разошедшуюся историю силой не чинить: показать, объяснить
простыми словами и дать выбрать.

**4. Не трогать чужое.** Обновление не касается ничего из этого, и сказать это надо вслух до
начала:

- `data/`, скачанные данные статистики, иногда гигабайты;
- `runs/` и любые файлы отчетов, названные вручную;
- `.env` и любые ключи;
- локальные правки в `config/`, если человек их делал.

**5. Половинчатого обновления не бывает.** Не получилось довести до конца, вернуть как было и
сказать прямо, а не оставлять дерево между версиями.

## Шаги

```bash
cd ~/mantoz
git status --short          # грязное дерево, остановиться и назвать файлы
git fetch origin
git log --oneline HEAD..origin/main   # показать, что приедет
```

Если список пустой, сказать «у вас уже текущая версия» и закончить. Не делать вид, что работа была.

```bash
git pull --ff-only origin main
uv pip install -e .
```

После обновления обязательно прогнать обе проверки и показать вывод целиком:

```bash
bash scripts/mantoz-selfcheck.sh --selftest
sh evals/licence_boundary_gate.sh
```

Первая проверяет, что дерево цело: схемы читаются, граф зависимостей без циклов, реестр источников
по-прежнему различает, что можно отдавать наружу. Вторая проверяет, что данные и производное от них
не уехали под git.

Красная проверка это стоп и разбор. Не «наверное, само пройдет».

## Ставили из ZIP

Скачайте новый архив
<https://github.com/zarubinvibe/mantoz/archive/refs/heads/main.zip>, распакуйте рядом и перенесите
в новую папку `data/`, `runs/` и `.env`, если они у вас есть. Старую папку не удаляйте, пока новая
не прошла обе проверки.

## Что сказать в конце

Три строки: с какой версии на какую перешли, что изменилось из важного, что осталось нетронутым.
Если что-то сломалось, назвать это первым, а не последним.
