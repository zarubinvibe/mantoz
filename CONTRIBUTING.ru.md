Спасибо, что заглянули. Быстрее всего проходят маленькие точные изменения.

## Установка

```bash
git clone https://github.com/zarubinvibe/mantoz.git
cd mantoz
bash install.sh
uv run pytest
uv run ruff check .
```

`install.sh` называет все, что у него не вышло, вместо тихого падения. Если он говорит, что нет uv
или Docker, офлайн-проверки все равно проходят и показывают, цело ли дерево.

## Путь изменения

1. Сделайте fork репозитория.
2. Заведите ветку: `git checkout -b fix-survey-timeout`.
3. Внесите правку и добавьте на нее тест.
4. Прогоните `uv run pytest`, `uv run ruff check .` и `bash scripts/mantoz-selfcheck.sh --selftest`.
5. Прогоните `sh evals/licence_boundary_gate.sh`, если трогали `config/` или граунд.
6. Оформите коммит по схеме `<type>: <описание>`: `fix: среда survey перестает ждать через 30с`.
7. Отправьте ветку и откройте Pull Request.

Не пушьте прямо в `main`: релизный gate такой push отклонит.

## Что примут

- Исправление бага с тестом, который до правки падает, а после проходит.
- Новую задачу в `application/tasks/` со своим верификатором внутри.
- Новый sandbox-бэкенд за `BaseEnvironment` из Harbor, добавленный рядом с существующими.
- Документацию, которая исправляет ошибку.

## Что не примут

- Источник граунда без письменного разрешения на коммерческое использование. Условия читаются на
  странице, которая реально отдает файл, а не на описании проекта, и цитируются в Pull Request.
- Все, что заводит под контроль версий данные, производные маргиналы или веса моделей.
- Вендоренную копию Harbor. Он остается объявленной зависимостью с атрибуцией в `NOTICE`.
- Верификацию, сведенную к одному-двум агентам-ревьюерам. Здесь она нарочно принадлежит задаче и
  работает на масштабе популяции.
- Второе дерево планирования. Требования лежат в `queue/GOAL.md`, решения в `docs/DECISIONS.md`.

## Как сообщить о проблеме

Заведите issue и напишите, что запускали, чего ждали и что вышло. Приложите команду и первые строки
ошибки. Прогон, который падает в одной среде и работает в другой, сам по себе полезная улика, так
что укажите, какую из четырех использовали.

Вопросы безопасности идут в [SECURITY.md](SECURITY.md), а не в публичный issue.
