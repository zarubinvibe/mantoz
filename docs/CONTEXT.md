Формат Покока: термин - одно-два предложения, `_Избегать:_` - только синонимы, которые в текстах
Mantoz значат то же самое (общеупотребимые слова в запрет не входят). Только термины, уникальные для
этого проекта - общие программистские понятия (агент, таск, датасет) сюда не входят, если не несут
здесь специфического смысла сверх обычного. Источник фактов - грил архитектуры 05.09.2026
(`mantoz-architecture-grill-outcome`), второй источник правды не заводится.

## Исполнение агентов

- **Harbor** - вендоренная OSS-зависимость (github.com/harbor-framework/harbor, Apache-2.0), берется
  кодом (pip/git с атрибуцией лицензии), не переписывается заново. Дает `BaseEnvironment` ABC для
  sandbox-бэкендов и весь реестр агентов - Mantoz наследует их функциональный охват целиком самим
  фактом зависимости. _Избегать:_ фреймворк исполнения, ядро агентов, движок.
- **Pluggable sandbox-бэкенд** - сменная реализация `BaseEnvironment`, под которой агент реально
  исполняется; выбор идет конфигом, не зашит в коде. MVP держит минимум два: self-hosted Docker
  Swarm/k3s (бесплатный дефолт) и Modal (платный opt-in). _Избегать:_ движок песочницы, executor,
  рантайм агента, окружение исполнения.
- **Среда задачи** - один из четырех форматов, в котором персона взаимодействует с продуктом: Survey,
  Chat, Web, App. Не путать с sandbox-бэкендом - среда задачи про то, ЧТО видит персона, бэкенд про то,
  ГДЕ физически крутится агент. _Избегать:_ канал, интерфейс, режим, платформа.

## Верификация

- **Oracle-агент** - агент с заведомо верным решением задачи, которым калибруют верификатор: если
  проверка не пропускает Oracle-агента, сломана проверка, а не персона. _Избегать:_ baseline,
  baseline-агент, эталонный агент, golden-прогон, sanity-агент.
- **Task-контракт** - тройка на одну задачу: `task.toml` (метаданные и лимиты), `instruction.md`
  (промт агенту), verifier (машинная проверка ответа). Формат, который видят одинаково агент,
  Oracle-агент и верификатор - унаследован от MatrAIx/Harbor как единица 100%-паритета по подсистеме
  task-contract. _Избегать:_ таск-спека, конфиг задачи, задание.
- **Population-scale верификация** - агрегация статистики верификатора по огромному числу прогонов
  персон (не 1-2 агента), с выводом на уровне подгруппы или всей популяции, а не одного прогона. Это
  архитектурный столп Mantoz, не опция - отличает его от точечной ревью-модели Helioz (Проверяющий на
  одну задачу). _Избегать:_ массовая проверка, батч-верификация, статистический тест, эвал на выборке.

## Персоны и граунд

- **Персона-схема** - структурное описание одной синтетической персоны (атрибуты и их DAG-зависимости
  друг от друга), по которому генератор строит датасет персон. Своя, полного масштаба, без урезания
  относительно MatrAIx. _Избегать:_ профиль персоны, персона-модель, схема пользователя.
- **DAG-генератор персон** - собственный синтетический генератор персон с нуля, строящий значения
  атрибутов персона-схемы по графу зависимостей между ними. Persona1M (Hugging Face, лицензия
  `matraix-research-only`) участвует только как bootstrap для наладки этого генератора, не как
  источник продакшн-данных. _Избегать:_ генератор датасета, синтезатор персон, конструктор персон.
- **Human grounding** - калибровка распределений персона-схемы по настоящим социологическим данным
  (опросы, микроданные), а не только по синтетике генератора. Первый источник - РМЭЗ-ВШЭ, второй,
  параллельно, - открытые микроданные Росстата/ЦБ (оба бесплатны и разрешают коммерческое
  использование); международный (US-эквивалент через GSS/WVS) откладывается до бесплатной замены или
  отдельного решения владельца платить за лицензию. _Избегать:_ граунд, калибровка на людях,
  реальные данные, ground truth персон.

## Приемка

- **100%-паритет** - критерий приемки Mantoz: построчное покрытие функционального чек-листа,
  построенного из 7-подсистемного аудита MatrAIx (persona / task-контракт / harbor / playground /
  packages / deployment / testing) - по каждой строке либо есть эквивалент, либо отсутствие
  обосновано как операционный шум, а не как недостающая функция. Мерится этим чек-листом, не
  ощущением "похоже по духу". _Избегать:_ MVP, MVP-срез, соответствие MatrAIx, готовность.
